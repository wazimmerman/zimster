# Zimster v0.2 Operational Controls and Packaging Plan

## Outcome

Correct the accidental v0.1 gaps identified by the Codex smoke audit while preserving Zimster's owner-driven, proof-first architecture. Produce a valid Codex repo marketplace layout, explicit Git and review disposition rules, stronger TDD falsifiability, canonical verification discovery, deterministic risk profiles, local evidence receipts, auditable model routing, safer reviewer roles, deterministic durable-state triggers, complete blocker states, synchronized release tooling, rebuilt packages, and an upgrade patch from v0.1.0.

## Binding requirements

- Treat the user's twelve-item audit as the approved change specification.
- Keep Codex the priority integration while preserving Claude Code and portable adapters.
- Reuse authoritative upstream mechanisms where practical; vendor the official Codex plugin validator rather than approximating its manifest schema.
- Keep runtime behavior local and private; evidence receipts must not upload telemetry.
- Preserve the compact skill set and persistent-owner execution model.
- Do not claim live harness compatibility that is not exercised in this environment.

## Vertical slices

### Slice 1 — Authoritative Codex packaging

- Move the repo marketplace target to `plugins/zimster/`.
- Remove unsupported Codex manifest fields.
- Vendor and run the official OpenAI Codex plugin validator.
- Validate the repo marketplace entry and packaged plugin layout.
- Package Codex with the plugin rooted at `plugins/zimster/` plus `.agents/plugins/marketplace.json`.

**Proof obligation:** the vendored official validator accepts the staged Codex plugin, tests reject `hooks` and root-level `./` marketplace sources, and the archive contains the marketplace-compatible layout.

### Slice 2 — Git lifecycle and review completeness

- Define default-branch, feature-branch/worktree, commit-boundary, delegated-commit, no-commit, and completion-disposition rules.
- Require review of staged, unstaged, and untracked files.
- Require final branch-finishing invocation and explicit repository disposition.
- Add deterministic durable-state creation triggers and `BLOCKED_BY_REQUIREMENT`.

**Proof obligation:** policy tests assert the complete lifecycle and no completion-ready state can ignore untracked files.

### Slice 3 — TDD, command discovery, and risk profiles

- Require meaningful per-behavior RED evidence for multi-behavior work via incremental cycles, incomplete stubs, or mutation checks.
- Prefer project-declared verification commands and classify baseline/focused/full outcomes precisely.
- Map risk dimensions deterministically to Micro, Standard, and High-risk profiles and require rationale in the run record.

**Proof obligation:** tests assert these contracts and reject blanket import-failure RED as sufficient for a multi-behavior feature.

### Slice 4 — Evidence and dispatch controls

- Add a local evidence receipt schema and CLI for recording/listing/checking command evidence against Git and working-tree fingerprints.
- Add duplicate-command awareness and invalidation status.
- Add a dispatch record schema and abstract Fast/Standard/Expert routing table with requested/effective model and effort fields.
- Remove unrestricted Bash from pure read-only roles; distinguish pure review from test-capable review and require tree-integrity checks when commands run.

**Proof obligation:** CLI tests cover valid reuse, dirty-tree invalidation, duplicate detection, and dispatch record validation; agent definitions expose only intended tools.

### Slice 5 — Release integrity, docs, and artifacts

- Add synchronized version-bump tooling.
- Enforce tag/version equality in release CI.
- Update manifests, marketplace metadata, changelog, README, architecture, porting, upstream notices, and evaluation docs.
- Bump to v0.2.0.
- Run final tests, validation, packaging, official Codex validation, Git checks, and artifact integrity checks.
- Produce source ZIP, Git bundle, Codex ZIP, Claude ZIP, portable ZIP, SHA-256 file, and v0.1.0→v0.2.0 patch.

**Proof obligation:** all version-bearing files agree, release-tag verification is tested, packages are deterministic, and the patch applies cleanly to the v0.1.0 base.

## Commit boundaries

1. Test contracts and plan.
2. Codex packaging and authoritative validation.
3. Workflow policy corrections.
4. Evidence and model-routing controls.
5. Release integrity and documentation.
6. Final verification corrections, if any.

## Completion states

- `CODE_READY` only after automated source/package gates pass.
- `PLUGIN_STRUCTURE_VERIFIED` after official Codex validator and local package-layout tests pass.
- `LIVE_CODEX_VERIFIED` and `LIVE_CLAUDE_VERIFIED` remain unavailable unless actual harness installs are run.
- Any contradictory or impossible requirement uses `BLOCKED_BY_REQUIREMENT`.
