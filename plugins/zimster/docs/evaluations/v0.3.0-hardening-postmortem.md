# Zimster 0.3.0 hardening postmortem

Date: 2026-07-28. This is a historical evaluation record, not a claim about
0.4.0 performance.

## Observed metrics

- goal meter: 1,328,242 tokens;
- elapsed time: approximately 7,173 seconds;
- logical implementation owners: 1;
- physical root contexts: 4 (the initial context plus 3 compactions);
- raw root input tokens: 74.4 million, predominantly cached;
- internal command-authorization turns: 125;
- web-research events: 35;
- surplus recognized file rereads: 120;
- objective reads: 14;
- exact-duplicate command executions: at least 48;
- complete-suite invocations: 11, of which 10 succeeded;
- review seams: 2;
- resumed rechecks: 2;
- owner correction waves: 4.

The goal meter and raw-input meter are reported separately because they are
incompatible measurements and must not be summed.

## Inference

The dominant cost was repeated root-context processing and model-driven command
orchestration, not deliberate agent count. Repeated broad verification,
objective/file rereads, authorization turns, and research consumed more than
the bounded specialist topology.

## 0.4.0 response

Version 0.4.0 moves deterministic gates into one compact verification runner,
enforces execution budgets, creates phase-bounded checkpoints, reuses
tree-keyed evidence, tests exact installed candidates before final review,
generates compact immutable review packages, scopes research through a dated
capability cache, and produces a run-scoped postmortem. These mechanisms are
evaluation hypotheses until paired benchmark results establish a quality and
economy gain.
